# 구축기사 등록 기준

첫 버전은 `public/data/articles.json`에 원문을 대조한 기사를 직접 등록한다.
웹 검색/이미지 인식은 후보를 찾는 데만 사용한다. 검색 결과에 등장한 이름이나
첫 번째 파티 이미지가 작성자의 최종 사용 파티라는 보장은 없다.
후보 수집과 1차 추출은 `npm run articles`가 맡는다([docs/article-collection.md](article-collection.md)).
그 결과는 `pending`으로만 들어오며, 아래 기준으로 사람이 확인해야 공개된다.
서버 DB와 순위의 공식 인증은 제공하지 않는다.

## 기사 추가

1. 원문에서 게임(챔피언스), 시즌, 싱글/더블, 작성자와 **최종** 순위를 확인한다.
   최고/중간 순위나 월간 챌린지 성적을 랭크배틀 최종 순위로 넣지 않는다.
2. 최종 파티 여섯 마리와 도구를 구성 경위, 개별 해설, 작성자의 인게임 팀
   이미지와 대조한다. 이미지의 별명을 포켓몬 종 이름으로 착각하지 않는다.
3. 참고 파티, 상대 파티, 과거 시즌 파티, 교체 전 구성은 제외한다.
   본문과 이미지가 충돌하면 수정 시점과 최종 구성 여부를 확인하고, 해결할 수
   없으면 `review.status: "pending"`으로 두어 공개하지 않는다.
4. 포켓몬/도구는 `reference.json`의 키를 쓴다. 메가는 실제 최종 메가 폼을
   기록한다. 도구가 **없음이 확인된 경우만** `item: null`로 쓴다.
   모르는 도구를 없음으로 치환하지 않는다.
5. `review`에 확인 날짜, 원문 이미지 주소(있을 때), `teamEvidence`,
   `rankEvidence`를 자체 문장으로 기록한다. 레이팅은 현재 표시하지 않는다.
6. 작성자별 원문 URL 중복과 원문 수정 여부를 확인한 뒤 `reviewed`로 변경한다.
   `updatedAt`을 갱신하고 `node --test tests/articles.test.mjs`를 실행한다.
7. 월간 챌린지(MCS) 순위가 제목에 함께 있으면 랭크배틀 최종 순위만 쓴다.
   큐가 `monthly-challenge` 플래그로 알려준다.

UI는 `reviewed`이며 필수 근거와 여섯 유효 구성원이 있는 기록만 표시한다.
이 검사는 입력 형식 검증이며, 본문 의미를 자동 판독하거나 사실을 보증하지 않는다.
원문 전문과 이미지는 재배포하지 않고 제목, 작성자, 파티 사실 정보, 링크를 표시한다.

## 조회

- `#articles`: 기사 카테고리. 최초에는 수록된 가장 최근 시즌을 선택한다.
- 시즌/형식/검색은 통계 랭킹의 선택과 독립적이다.
- 형식은 ‘전체 형식’도 고를 수 있다. 최종 순위 범위(10·50·100·1000위 이내)로 좁히고,
  최종 순위순(최근 시즌부터)과 최근 게시순으로 정렬한다.
- 검색어는 공백으로 나눈 낱말을 **모두** 포함하는 파티를 찾는다. ‘한카리아스 팬텀’은
  둘 다 채용한 파티다.
- 목록 위의 ‘채용이 많은 포켓몬’은 지금 목록의 파티에서 포켓몬별 채용 수를 센다.
  누르면 조건에 더해지고, 조건이 있으면 ‘함께 채용된 포켓몬’이 된다. 여러 마리를
  고르면 모두 채용한 파티만 남는다. 메가 폼은 기본 종족으로 센다.
- 포켓몬 상세의 구축기사 탭은 선택한 통계 시즌과 배틀 형식으로 제한한다.
- ‘다른 시즌 기사 보기’는 포켓몬 조건을 유지하고 전체 시즌 목록을 연다.
- 일반 포켓몬을 찾으면 그 포켓몬의 메가 폼 채용도 포함한다. 지역 폼과
  다른 메가 폼끼리는 자동으로 합치지 않는다.
- M-5 싱글 두 건으로 시작한다. 빈 목록은 미수록일 수 있으며 해당 포켓몬을
  채용한 상위 랭커가 없다는 뜻이 아니다.

두 초기 기록은 작성자의 최종 팀 이미지와 본문을 대조했다. 특히 rebo 기사에서는
첫 트레이너 카드, 교체된 아머까오, 한카리아스의 교체 전 기합의띠를 배제했다.
