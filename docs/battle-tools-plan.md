# 배틀 어시스트 · 엔트리 픽 · 파티 상성과 추천 설계

작성 2026-09-25. 구현 전 설계다. 세 기능은 같은 계산 한 벌(아래 `대면 코어`)을 공유하므로
그것부터 만들고, 기능은 그 위에 얇게 올린다.

## 0. 쓸 수 있는 자료

기능을 정하기 전에 무엇을 **알 수 없는지**부터 적는다.

| 자료 | 있음 | 비고 |
| --- | --- | --- |
| 사용 순위 (`position`) | 있음 | 사용률 % 자체는 없음 |
| 기술·도구·특성·성격 채용률 | 있음 | 상위 행만 |
| 능력 포인트 배분 채용률 | 있음 | 상위 행만 |
| 같은 팀 (`teammate`) | 순위만 | 비율 없음 |
| **승률** | **없음** | 제공처가 공개하지 않는다 |
| **선출률·선봉률** | **없음** | 〃 |
| 구축 기사 파티 | 있음 | 수록한 만큼만. 선출 정보 없음 |
| 종족값·상성·데미지·스피드 계산 | 있음 | `reference.json`, `damage-calc.js`, `speed-calc.js` |

championsbattledata의 데스크톱 컴패니언(오버레이를 하는 그 앱)은 게임 화면을 읽어 **자기
사용자 데이터로** 선봉·선출 제안을 만든다. 공개 JSON에는 승률·선출률이 없다. 이 앱이
‘승률’을 보여주려면 사용자가 자기 대전 결과를 기록하는 수밖에 없다(7절).

따라서 세 기능의 값은 **통계를 보여주는 것**이 아니라 **내 샘플과 상대의 유력 배치를
서로 계산해 주는 것**에 있다. 통계만 보여주면 사용자가 직접 찾는 것과 다르지 않다.

## 1. 대면 코어 (`src/matchup.js`, DOM 없음)

### 1-1 유력 배치 펼치기

상대 포켓몬 하나를 통계에서 **가중 배치 몇 개**로 펼친다.

- 도구, 특성, 성격, 포인트 배분의 상위 행을 조합하되 서로 독립이라고 가정한다
  (통계가 결합 분포를 주지 않는다). 가중치는 채용률의 곱.
- 조합 폭발을 막으려고 누적 가중치 80%에 이를 때까지만, 최대 8개까지 둔다.
- 기술은 채용률 상위 네 개를 기본으로 하되, 데미지 계산은 채용률 30% 이상인 공격 기술을
  모두 본다(4번째 기술이 갈리는 경우).
- 결과는 `{ weight, item, ability, nature, points, moves }[]`. 화면에는 ‘가장 흔한
  배치’ 한 줄과 ‘스카프 23%’처럼 결과를 뒤집는 변수만 따로 보인다.

### 1-2 1:1 대면 점수

내 샘플 A와 상대 B(펼친 배치들)에 대해, 배치마다 계산하고 가중 평균한다.

1. 스피드: 스카프·랭크 없는 기본 상태에서 누가 먼저인가(`speed-calc.js`). 동속은 0.5.
2. 데미지: A의 최선 기술이 B에게 주는 최소~최대 %, B의 최선 기술이 A에게 주는 %
   (`damage-calc.js`). 여기서 **몇 번에 쓰러뜨리는가**(난수 포함 확률)를 얻는다.
3. 판정: A가 B를 쓰러뜨리는 턴 수 `tA`, B가 A를 쓰러뜨리는 턴 수 `tB`.
   `tA < tB`면 A 승, `tA > tB`면 B 승, 같으면 선공이 이긴다. 기합의띠·멀티스케일은
   1타를 버티게 하므로 턴 수에 반영한다.
4. 점수 `M[A][B]` = A가 이길 확률(배치 가중·난수 반영), 0~1.

교체·변화기·상태이상은 1차 범위에서 뺀다. 대신 화면에 ‘1:1 맞대면 기준’이라고 적는다.
이것만으로도 ‘상대 스카프 채용 23% → 이 대면은 62%로 떨어짐’처럼 통계만으로는 안
보이는 정보가 나온다.

### 1-3 검증

기존 `damage-calc.test.mjs`가 Showdown 계산기와 맞춰 둔 값을 그대로 쓴다. 코어의
테스트는 ‘스카프를 넣으면 선공이 바뀌어 판정이 뒤집힌다’, ‘띠 가중치가 턴 수에 반영된다’
같은 규칙 단위로 둔다.

## 2. 배틀 어시스트 (오버레이 없는 판)

### 무엇이 다른가

직접 통계를 찾는 것과의 차이를 기능 요구로 적는다.

| 직접 찾으면 | 어시스트는 |
| --- | --- |
| 여섯 마리 상세를 하나씩 연다 | 한 화면에 여섯 마리의 핵심만 |
| ‘스카프 23%’를 보고 머리로 스피드 비교 | 내 파티 각각과 선후를 계산해 표시 |
| 데미지 계산기에 배치를 옮겨 넣는다 | 유력 배치로 양방향 확정 타수를 바로 |
| 기사를 따로 검색 | 상대 여섯 마리와 겹치는 구축 기사를 붙인다 |

### 흐름

1. 내 파티 고르기 — `내 샘플`의 파티를 쓴다(이미 있음).
2. 상대 여섯 마리 입력 — 선출 화면에서 보고 치는 시간이 짧아야 한다. 초성 검색 한 칸,
   고르면 칸이 비고 다음 입력으로. 최근 입력한 상대 파티를 목록으로 남긴다(같은 파티를
   자주 만난다). 사용 순위 상위를 먼저 제안한다.
3. 결과 화면
   - 상대 × 내 파티 6×6 격자. 칸에 `M[A][B]`를 색으로, 누르면 대면 카드.
   - 대면 카드: 스피드 선후(배치별), 양방향 데미지 범위와 확정 타수, 결과를 뒤집는 변수
     (도구·특성 채용률), 그 포켓몬의 채용 기술 상위.
   - 상대 여섯 중 k마리 이상 겹치는 구축 기사(3절의 선출과 별개로 ‘이런 구성일 수 있다’).
4. 대전 중: 상대가 낸 포켓몬을 누르면 그 줄만 크게 보인다. 도구·특성이 드러나면
   눌러서 고정하고, 고정하면 배치 펼치기가 그 값으로 좁혀진다.

오버레이는 하지 않는다. 안드로이드 PWA에서 다른 앱 위에 그릴 수 없다. 분할 화면에서
쓰기 좋도록 좁은 폭(360px)을 기본 배치로 설계한다.

## 3. 엔트리 픽 (선출 추천)

싱글은 6에서 3, 더블은 6에서 4. 대면 코어의 6×6 행렬 `M`을 입력으로 한다.

### 싱글

1. 상대 선출 확률: 상대 여섯 마리 각각이 뽑힐 가중치 `p_j`. 선출률 자료가 없으므로
   사용 순위를 대신 쓴다(`p_j ∝ 1/√position`). 사용자가 ‘반드시 나온다’로 고정할 수 있다.
2. 내 3마리 조합 20개 × 상대 3마리 조합 20개를 모두 본다(400쌍, 즉시 계산됨).
3. 조합 대 조합 점수: 상대 각 마리에 대해 내 3마리 중 가장 잘 받는 쪽의 `M`
   (답이 있는가)을 평균하고, 내 한 마리가 상대 둘 이상에게 지면 감점(한 마리에 몰림).
4. 내 조합 점수 = 상대 조합들에 대한 가중 기대값과 **최악값**을 함께 본다. 기본 정렬은
   `0.7 × 기대 + 0.3 × 최악`. 운에 덜 기대는 선출을 위로 올린다.
5. 선봉: 고른 조합 안에서 상대의 유력 선봉(사용 순위 상위 1~2) 대면 점수가 가장 높은
   쪽을 선봉으로 제안한다.

### 더블

같은 틀에 4마리, 선봉 2마리. 1:1 대면은 더블을 잘 설명하지 못하므로 1차는
‘상대 각 마리에 대한 답의 수’와 `전체기 피해`만 보고, 순풍·트릭룸·위협처럼 더블에서
판을 바꾸는 기술 채용을 따로 표시한다. 더블의 정교한 계산은 후속.

### 설명이 점수보다 중요하다

추천마다 이유를 붙인다. ‘상대 한카리아스에 대한 답: 내 누리레느(선공 확1 78%)’,
‘상대 팬텀을 받을 포켓몬이 없음’. 사용자가 점수를 믿지 않아도 이유를 보고 판단할 수 있다.

## 4. 파티 상성 확인

내 파티(샘플 여섯)를 입력으로 한다. 샘플이 있으니 **실제 채용 기술**로 계산한다.

- 방어 상성: 18타입 각각에 대해 약점·반감·무효 수. 특성(부유·저수 등)은 이미 있는
  `defenseChart`의 선택 특성 처리를 그대로 쓴다. ‘약점 3 이상이고 반감 0’인 타입을 경고.
- 공격 범위: 채용 기술로 18타입 각각에 효과 굉장함을 낼 수 있는 포켓몬 수.
- 환경 위협 검사(핵심): 사용 순위 상위 N(기본 30) 각각에 대해, 가장 흔한 배치로
  내 파티 중 (a) 선공으로 2타 안에 잡는 포켓몬, (b) 그 포켓몬의 채용 기술을 50% 이하로
  받는 포켓몬이 있는지. 둘 다 없으면 **위협**. 순위가 높을수록 위에 둔다.
- 역할 표(아래 5-2)로 ‘스텔스록 없음’, ‘고속 포켓몬 없음’ 같은 빈칸을 보인다.

## 5. 빈자리 추천

### 5-1 점수

후보는 현재 시즌 사용 순위 상위 100 중 파티에 없는 포켓몬, 가장 흔한 배치 기준.
네 항목을 0~1로 맞추고 가중 합한다. 가중치는 화면에 보이고 사용자가 바꿀 수 있다.

| 항목 | 기본 가중치 | 계산 |
| --- | --- | --- |
| 위협 해소 | 0.4 | 4절의 위협 중 이 후보가 (a) 또는 (b)로 답하는 수, 위협 순위로 가중 |
| 상성 보완 | 0.25 | 파티가 공통으로 약한 타입을 반감·무효로 받는가, 새 공통 약점을 만드는가 |
| 함께 채용 | 0.2 | 현재 멤버들의 `teammate` 목록에서 이 후보의 순위 `1/rank` 합 + 구축 기사 동시 채용 수 |
| 역할 채움 | 0.15 | 파티에 없는 역할을 이 후보가 채우는가 |

`teammate`에는 비율이 없어 순위만 쓴다. 구축 기사는 수는 적지만 실제 여섯 마리
조합이라, 기사 목록의 ‘함께 채용된 포켓몬’ 집계(`articleUsage`)를 그대로 쓴다.

메가는 한 파티에 여럿 들어갈 수 있지만 한 대전에서 한 번만 메가진화하므로, 이미 메가가
둘 이상이면 메가 후보를 감점한다.

### 5-2 역할은 손으로 붙이지 않고 통계에서 읽는다

다른 앱이 말하는 ‘유틸’, ‘고속 서포터’는 정해진 규칙이 공개되어 있지 않다. 이 앱은
**채용률로 정의하고 정의를 화면에 보인다.** 기준은 모두 채용률 30% 이상.

| 역할 | 정의 |
| --- | --- |
| 고속 | 가장 흔한 배치의 실수치 스피드가 환경 상위 30의 중앙값 이상, 또는 구애스카프 채용 |
| 설치 | 스텔스록·압정뿌리기·독압정·끈적끈적네트 |
| 서포트 | 도발·전기자석파·도깨비불·하품·앵콜·리플렉터·빛의장막·순풍·트릭룸 |
| 고속 서포터 | 고속 ∧ 서포트 |
| 피벗 | 유턴·볼트체인지·퀵턴·막말내뱉기·순간이동(교체 기술) |
| 날씨·필드 시동 | 가뭄·잔비·모래날림·눈퍼뜨리기·필드 특성 |
| 쌓기 에이스 | 칼춤·용의춤·나비춤·명상·껍질깨기 등 |
| 쿠션 | HP×방어 또는 HP×특방 상위 25% ∧ 회복 기술 또는 먹다남은음식 |

목록은 한 파일(`src/roles.js`)에 두고 기술 키로 적는다. 기준을 바꾸면 테스트가 드러낸다.

## 6. 구현 순서

1. `src/matchup.js`: 배치 펼치기, 1:1 대면 점수. 테스트 먼저.
2. 파티 상성 확인(4절 중 방어·공격 범위): 코어 없이도 되는 부분이라 먼저 낸다.
3. 배틀 어시스트: 상대 입력 + 6×6 격자 + 대면 카드 + 겹치는 기사.
4. 엔트리 픽: 격자 위에 조합 탐색과 이유 문장.
5. 환경 위협 검사와 빈자리 추천, 역할 표.

2가 가장 싸고 5가 가장 비싸다. 1은 3~5 모두의 전제다.

## 7. 하지 않는 것, 뒤로 미루는 것

- 오버레이·화면 인식 — PWA로 불가능. 필요하면 별도 데스크톱 앱이 된다.
- 승률 표시 — 공개 자료가 없다. 후속으로 ‘내 대전 기록’(상대 여섯, 내 선출, 승패)을
  남기면 **내 기록 기준** 승률과 상대 파티별 전적은 만들 수 있다. 동기화가 이미 있어
  저장 구조만 더하면 된다.
- 교체·상태이상·날씨 시동을 포함한 다턴 시뮬레이션 — 1:1 대면으로 시작하고, 설명이
  맞지 않는 사례가 모이면 그때 넓힌다.
