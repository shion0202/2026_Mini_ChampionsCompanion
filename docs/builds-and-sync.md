# 샘플과 파티 저장 (2026-09-22)

포켓몬 하나의 배치를 ‘샘플’, 여섯 마리의 조합을 ‘파티’로 저장하고 목록에서
확인한다. PC와 안드로이드에서 같은 목록을 보며, 파티를 읽기 전용 링크로
남에게 보여줄 수 있다.

안드로이드는 웹앱이 아니라 APK로 받는다. PC가 꺼져 있어도 단독으로 동작해야
한다.

## 데이터 모델

```
sample {
  id, name, note,
  pokemon, form,
  ability, up, down, points[6],
  moves[4], altMoves[],
  updatedAt
}
party { id, name, note, members[6], updatedAt }
doc  { samples[], parties[], version }
```

- `pokemon`은 통계와 같은 영문 이름을 그대로 쓴다. `form`은 폼이 없으면 null이다.
  한국어 표시는 기존 `locale.js`가 맡으므로 저장은 영문 이름으로 통일한다. 기술·
  도구·특성도 같은 이유로 영문 이름을 저장한다.
- 능력 보정은 성격 이름이 아니라 `up`과 `down` 두 능력으로 저장한다. 통계가
  성격 이름을 주지 않고 올리는/내리는 능력만 주며, 앱도 성격 목록을 들고 있지
  않다. `#speed=battle`의 프리셋 판정과 같은 형식이다.
- `points`는 HP, 공격, 방어, 특공, 특방, 스피드 순서다. 각 칸은 0 이상 32 이하
  정수이며 합계는 66 이하다. 통계 자료의 검증 규칙과 같은 범위를 쓴다. 자체
  기준을 따로 만들면 게임이 허용하는 배치를 거절할 수 있다.
- `altMoves`는 채용 기술 4개 외에 취향이나 메타에 따라 바꿀 수 있는 후보다.
  개수 제한을 두지 않는다. 후보마다 개별 메모를 두지 않고 `note` 하나에 적는다.
  여러 후보가 같은 이유를 공유하는 경우가 많아 후보별로 쪼개면 같은 문장을
  반복하게 된다.
- 채용 기술과 후보 기술은 **자리를 맞바꾼다.** 채용 기술 하나를 이미 후보에 있는
  기술로 바꾸면, 후보의 그 자리에 원래 채용하던 기술이 들어간다. `moves`가
  A·B·C·D이고 `altMoves`가 E·F·G일 때 D를 E로 바꾸면 A·B·C·E와 D·F·G가 된다.
  교체는 후보를 소비하는 것이 아니라 뒤바꾸는 것이므로 후보 개수가 줄지 않고
  후보 목록의 순서도 유지된다.
- 후보에 없는 기술로 바꿀 때는 맞바꾸지 않는다. 원래 기술은 그냥 빠지고
  `altMoves`는 그대로다. 후보로 남기고 싶으면 직접 추가한다. 고르는 기술마다
  후보 목록이 자동으로 늘어나면 목록이 의도와 무관하게 불어난다.
- 같은 기술이 `moves`와 `altMoves`에 동시에 있을 수 없고, 각 목록 안에서도
  중복될 수 없다.
- `note`에는 능력 보정과 포인트의 의도, 기술의 의도, 후보 기술인 이유를 적는다.
  서식 없는 여러 줄 글이다. 파티의 `note`에는 왜 이런 조합인지를 적는다.
- `members`는 길이 6의 배열이며 각 칸은 샘플 id이거나 빈 자리를 뜻하는 null이다.
  구상 중인 조합을 적어두는 것이 이 기능의 쓸모이므로 여섯 자리를 다 채우지
  않아도 저장되고 목록에 나온다.
- 샘플이 단일 진실이므로 배분을 한 번 고치면 그 샘플을 쓰는 모든 파티에
  반영된다. 샘플을 지울 때 그 샘플을 쓰는 파티 수를 세어 알리고, 확인을 받으면
  해당 자리를 null로 되돌린다.

## 화면

헤더에 ‘도감’ 옆으로 ‘내 샘플’을 둔다. `#builds=sample`, `#builds=party`로 바로
열 수 있다. 기존 `#dex=move`와 같은 방식이다.

- 목록은 이름으로 검색한다. 샘플은 포켓몬으로도 걸러진다.
- 새 샘플은 빈 값에서 시작한다. 통계의 상위 채용 기술이나 도구를 초깃값으로
  넣지 않는다. 쓰려는 배치가 통계와 다를 때 지우는 일이 채우는 일보다 번거롭고,
  넣어둔 값이 확인한 값처럼 보인다.
- 편집 중 이탈하면 저장하지 않은 내용을 알린다.

## 저장과 동기화

`localStorage`가 1차 저장소다. 저장하면 로컬에 먼저 쓰고 서버에 올린다. 서버가
실패해도 편집은 성립하며 ‘동기화 안 됨’을 표시하고 다음에 앱을 열 때 다시
올린다. 오프라인에서도 만들고 고칠 수 있어야 하므로 서버를 1차 저장소로 두지
않는다.

기기를 묶는 수단은 20자 난수 **동기화 코드** 하나다. PC에서 처음 저장할 때
만들고, 안드로이드에서 한 번 입력하면 같은 문서를 본다. 계정도 비밀번호도
없다.

- 코드를 가진 사람이 곧 그 문서의 전체 권한을 가진다. 개인용 앱이므로 이 교환을
  받아들인다.
- 코드를 잃으면 복구 수단이 없다. 그래서 JSON 내보내기·가져오기를 서버보다
  먼저 만든다.

올릴 때 읽어온 `version`을 함께 보낸다. 서버에 더 새 버전이 있으면 거부하고
‘다른 기기에서 바뀌었습니다. 새로 불러온 뒤 다시 저장하세요’를 띄운다. 조용히
덮어쓰지 않는다.

`ponytail: 문서를 통째로 저장하고 낙관적 잠금만 건다. 양쪽에서 동시에 자주
고치게 되면 항목별 키로 쪼갠다`

공유 링크는 원본을 참조하지 않고 그 시점의 스냅샷을 복사해 둔다. 파티의 샘플
참조도 이때 펼친다. 원본을 나중에 고쳐도 이미 보낸 링크는 그대로 남는다.

## API

Cloudflare Pages Functions로 정적 파일과 같은 프로젝트에서 `/api/*`를 처리한다.
Worker를 따로 배포하면 도메인과 CORS 설정이 늘어난다.

```
GET  /api/doc?key=<코드>     → { doc, version }
PUT  /api/doc?key=<코드>     → { version }  /  409 버전 충돌
POST /api/share?key=<코드>   → { id }
GET  /api/share/<id>         → 스냅샷 (코드 불필요, 읽기 전용)
```

KV 키는 `doc:<코드>`와 `share:<id>` 둘뿐이다. 자료가 작아 스키마를 두지 않는다.

서비스 워커는 손대지 않아도 `/api/*`를 거르지 않는다. `sw.js`의 fetch 처리가
`APP_FILES` 목록에 있는 주소만 가로채는 방식이라 목록에 없는 주소는 그대로
네트워크로 간다. 새로 추가한 `src/*.js`를 목록에 넣고 캐시 이름을 올리기만
한다.

## 배포와 APK

정적 파일은 Cloudflare Pages에 올린다. APK는 Bubblewrap으로 만든 TWA다. 지금
`manifest.webmanifest`와 `sw.js`가 이미 설치 기준을 만족하므로 추가 작업은
`.well-known/assetlinks.json`뿐이다.

앱을 고쳐도 APK를 다시 만들지 않는다. 웹사이트만 배포하면 반영된다. 서명 키
관리와 재설치 부담이 없는 것이 이 방식을 고른 이유다.

- 스토어를 거치지 않으므로 기기에서 ‘알 수 없는 출처’ 설치를 허용해야 한다.
- assetlinks 검증이 실패하면 주소창이 보이는 상태로 열린다. 동작은 하지만 앱처럼
  보이지 않으므로 배포 후 실제 기기에서 확인한다.
- 첫 실행에는 연결이 필요하다. 이후에는 서비스 워커가 캐시한 파일로 연결 없이
  열린다.

## 모듈

기존 `app-state` / `app-view` / `api` 분리를 그대로 따른다.

- `src/builds.js` — 모델과 검증. DOM을 쓰지 않는다.
- `src/builds-view.js` — 마크업 생성.
- `src/sync.js` — 서버 통신과 버전 충돌 처리.
- `functions/api/[[path]].js` — 위 네 엔드포인트.

`src/app.js`는 지금처럼 상태 보관과 DOM 조작, 이벤트 연결만 맡는다.

## 단계

1. **로컬 저장** — 샘플·파티 만들기, 고치기, 지우기, 목록, JSON 내보내기·
   가져오기. 서버 없이 PC에서 완결된다.
2. **배포와 APK** — Pages 배포, assetlinks, Bubblewrap. 이 시점에 안드로이드가
   단독으로 동작한다.
3. **동기화** — Functions와 KV, 동기화 코드.
4. **공유 링크**

각 단계는 그 자체로 쓸 수 있다. 3단계 전까지 기기 사이 이동은 1단계의 JSON
파일로 한다.

## 한도

Cloudflare 무료 플랜에서 쓰기는 하루 1,000회, 읽기는 10만 회다. 저장 한 번이
쓰기 한 번이고 링크 조회는 전부 읽기다. 개인과 지인 범위에서는 한도에 닿지
않는다. 수치는 3단계 시작 전에 현재 문서로 확인한다.

## 검증

  기술로 바꿨을 때의 맞바꿈과 후보에 없는 기술로 바꿨을 때의 비(非)맞바꿈,
  빈 자리가 있는 파티, 없는 샘플을 참조하는 파티, 내보낸 JSON을 다시 가져왔을

- `tests/sync.test.mjs` — 버전이 밀렸을 때 거부하는지, 실패한 올리기를 다시

  경고, 오프라인 편집 후 복귀 동기화, 360px과 PC 레이아웃을 확인한다.
