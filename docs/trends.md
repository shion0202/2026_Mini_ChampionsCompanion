# 사용률 추이

상단 메뉴 ‘사용률 추이’(`#trends=regulation|season|current`)와 랭킹 상세의 ‘추이’ 탭.
로직은 `src/trends.js`, 그래프는 `src/trends-view.js`, 배선은 `src/app.js`다.

## 자료

- 통계는 포켓몬 **순위**(`position`)만 준다. 사용률 %는 없으므로 순위 추이를 그린다.
- 진행 중인 시즌만 날짜별 자료가 있고, 지난 시즌은 최종일 자료 하나뿐이다.
- 레귤레이션은 API에 없다. `src/data.js`의 `SEASON_REGULATIONS`(공식 발표로 확인한
  것만)를 쓰고, 표에 없는 시즌은 추정하지 않고 뺀다. 새 시즌이 시작되면 이 표에 한 줄
  더한다.

| 기간 | 시점 |
| --- | --- |
| 레귤레이션별 | 레귤레이션마다 마지막 시즌의 최종일(진행 중이면 최신 날짜) |
| 시즌별 | 시즌마다 최종일 |
| 현재 시즌 | 진행 중인 시즌의 모든 날짜 |

2026-09-25에 본 바로는 M6의 첫날(9/11) 자료가 M5 최종일과 같다. 시즌이 바뀐 날에는
제공처가 이전 시즌 자료를 그대로 둔 것으로 보인다.

## 그리기

- 전체 그래프는 어느 한 시점이라도 100위 안에 든 포켓몬만 그린다. 100위 밖이거나
  자료가 없는 시점은 선을 끊는다. 양 끝에 순위 번호와 그 순위의 포켓몬 그림을 둔다.
  줄이나 그림을 누르면 그 포켓몬만 강조한다.
- 상세 탭은 포켓몬 하나의 실제 순위를 한계 없이 보인다. 순위에 없던 때는 ‘순위 밖’.

## 이용 규칙

제공처 규칙(https://championsbattledata.com/api-rules/)상 적당한 캐시는 되지만 영구
미러·아카이브는 안 된다. 그래서 받은 스냅샷에서 순위만 뽑아 **메모리에만** 두고
(`createTrendStore`), 서버(KV)나 저장소에 날짜별 자료를 모으지 않는다. 추이 화면에
출처(Battle data provided by Pokémon Champions Battle Data)를 적는다.
스냅샷 하나가 약 350KB라 현재 시즌 그래프는 수 MB를 받는다. 화면을 열 때만 받는다.
