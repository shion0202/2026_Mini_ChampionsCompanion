# 사용률 추이

상단 메뉴 ‘사용률 추이’(`#trends=current|season|regulation`)와 랭킹 상세의 ‘사용률 추이’ 탭.
둘 다 현재 시즌, 시즌별, 레귤레이션별 순서다.
로직은 `src/trends.js`, 그래프는 `src/trends-view.js`, 배선은 `src/app.js`다.

## 자료

- 통계는 포켓몬 **순위**(`position`)만 준다. 사용률 %는 없으므로 순위 추이를 그린다.
- 진행 중인 시즌만 날짜별 자료가 있고, 지난 시즌은 최종일 자료 하나뿐이다.
- 레귤레이션은 API에 없다. `src/data.js`의 `SEASON_REGULATIONS`(공식 발표로 확인한
  것만)를 쓰고, 표에 없는 시즌은 추정하지 않고 뺀다. 새 시즌이 시작되면 이 표에 한 줄
  더한다.

| 기간 | 시점 |
| --- | --- |
| 현재 시즌 | 진행 중인 시즌의 모든 날짜 |
| 시즌별 | 시즌마다 최종일 |
| 레귤레이션별 | 레귤레이션마다 마지막 시즌의 최종일(진행 중이면 최신 날짜) |

2026-09-25에 본 바로는 M6의 첫날(9/11) 자료가 M5 최종일과 거의 같다. 포켓몬 구성(235마리)이
같고, 싱글은 46위 아래 24마리, 더블은 8위 아래 63마리만 한두 칸 다르다. 9/12부터 261마리로
늘고 순위가 모두 바뀐다. 그래서 `dropCarryOver`는 현재 시즌 앞쪽에서 이전 시즌 최종일과
포켓몬 구성이 같은 날을 이전 시즌 자료로 보고 뺀다. 순위는 몇 칸 다를 수 있어 보지
않는다. 레귤레이션이 바뀌지 않는 시즌 전환에서도 첫날이 빠질 수 있다(2026-09-25 결정).

## 그리기

- 전체 그래프는 어느 한 시점이라도 100위 안에 든 포켓몬만 그린다. 양 끝에 순위 번호와
  그 순위의 포켓몬 그림을 둔다. 폭에 맞춰 열 간격을 늘려 왼쪽 끝에서 오른쪽 끝까지 채운다.
- 100위 밖에 있다가 들어온 선은 그래프 아래(‘밖’ 띠)에서 올라오고, 나간 선은 아래로
  빠진다. 두 열 사이 중간에서 빠져 선이 한 점에 뭉치지 않게 한다. 자료에 없다가 처음
  나온 포켓몬은 점에서 시작한다. 중간에 들어온 포켓몬은 들어온 자리에 그림을 둔다.
- 선이나 이미지를 누르면 해당 포켓몬만 강조한다.
- 상세 탭은 포켓몬 하나의 실제 순위를 한계 없이 보인다. 순위에 없던 때는 ‘순위 밖’.

## 이용 규칙

제공처 규칙(https://championsbattledata.com/api-rules/)상 적당한 캐시는 되지만 영구
미러·아카이브는 안 된다. 그래서 받은 스냅샷에서 순위만 뽑아 **메모리에만** 두고
(`createTrendStore`), 서버(KV)나 저장소에 날짜별 자료를 모으지 않는다. 추이 화면에
출처(Battle data provided by Pokémon Champions Battle Data)를 적는다.
스냅샷 하나가 약 350KB라 현재 시즌 그래프는 수 MB를 받는다. 화면을 열 때만 받는다.
